# 中药饮片炮制批次与质量放行平台

面向饮片厂质量受权人的连续批记录与放行平台。净制、切制、辅料加入、润制、
炒制、干燥、取样、包装八道工序形成连续批记录；只看最终检验值无法证明
炮制过程与物料转换受控，平台因此同时核对**物料逐克去向、工艺曲线、
偏差处置、报告样品链与放行范围**。

## 业务规则

- **数量守恒**（`process/ledger.py`）：领料、工序转换、拆分、合批、
  辅料吸入、取样、返工、偏差调账逐笔记账，每笔满足
  `投入 = 产出 + 损耗 + 取样`，全局满足
  `累计领料 = 各批现存 + 累计损耗 + 累计留样`，数量按 1 g 量化，
  差 1 g 的拆分也会被拒绝。
- **工艺版本与参数**（`process/specifications.py`）：按「品种 + 开工日
  生效版本」校验；酒炙当归现行 v2023（v2020 已停用）。炒制温度曲线
  相邻点间隔不得超过 60 秒，10 分钟缺口会被直接判出；温度越限同样判出。
- **签署与补传**（`process/records.py`）：未签署记录可由采集网关补传
  曲线（填补缺口）；操作人确认后曲线冻结，任何人不得改写，只能由 QA
  凭偏差单出具修正记录，原记录置 `corrected` 留痕，原始数据不覆盖。
- **偏差与权限分离**（`process/deviations.py`、`process/quality.py`、
  `process/release.py`）：操作人执行、传感器补传、QC 取样出报告、
  QA 评估/验证/关闭偏差、QP 最终放行，互不兼任。偏差须经
  评估→验证→关闭才能支持放行。
- **返工**：原批自动隔离，新批 `rework_of` 关联原批；新批必须**补采
  样品并重新出具本批报告**，引用原批或上一批报告一律拒绝放行。
- **放行评审**（`process/release.py`）：沿拆分/返工批次链汇总记录，
  核对守恒、八工序签署合规、偏差关闭、报告属于本批且样品取自本批、
  放行数量与台账现存一致。任何一条不满足都返回带原因的不予放行决定。

## 模块

| 文件 | 职责 |
| --- | --- |
| `process/contracts.py` | 物料批、移动、工序记录、偏差、样品、报告、放行决定 |
| `process/ledger.py` | 逐克守恒台账与批次谱系 |
| `process/specifications.py` | 品种工艺版本、参数限度、温度曲线缺口校验 |
| `process/records.py` | 记录登记、传感器补传、操作人签署、偏差修正 |
| `process/deviations.py` | 偏差状态机与 QA 权限 |
| `process/quality.py` | QC 取样、检验报告（禁止跨批引用样品） |
| `process/release.py` | QP 放行核对包与放行决定 |
| `process/scenario.py` | 从 fixture 构建完整情景 |
| `fixtures/processing_batch.json` | 酒炙当归一批：拆分、10 分钟缺口、收率差异、返工补采 |

## 运行

```bash
python -m compileall process          # 语法检查
python -m process.demo                # 质量受权人核对样例（含四个放行决定）
python -m unittest discover -s tests  # 29 个测试
```

## 样例剧情（proc-0915）

- `proc-0915-a` 领料当归 120 kg + 黄酒 15 kg，净制→润制后平分为
  a-1 / a-2 各 64.2 kg；
- **a-1**：炒制曲线 3 分钟缺口在签署前由网关补传，正常全检放行 55.6 kg；
- **a-2**：10 分钟缺口在操作人签署后才暴露 → 曲线冻结，QA 凭偏差单
  出具修正记录；收率对不上（车间报 111.6 kg），经偏差核定核减 0.1 kg；
  最终按偏差返工炒制，原批隔离，新批 `proc-0915-a-2-r1` 关联原批、
  补采 0.3 kg、重出报告后放行 52.8 kg；
- 车间引用上一批 `rpt-0914-legacy` 为 a-2 申请放行，被 QP 拒绝
  （同时列出缺口、未关闭偏差、报告跨批等全部原因）。

最终守恒：领料 135.000 = 现存 109.600（55.6 + 52.8 + 黄酒余 1.2）
+ 损耗 24.800 + 留样 0.600 kg。
