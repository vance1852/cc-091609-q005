# 中药饮片炮制与质量放行平台

一批酒炙当归炒制温度曲线有十分钟缺口、收率与领料量对不上，车间还引用上一批
检验报告申请放行——只看最终检验值，无法证明炮制过程受控与物料转换可核。
本平台用 Python 把 **净制、切制、辅料加入、润制、炒制、干燥、取样、包装**
建成一条受权限控制的连续批记录，并把每一次拆分、合批、损耗与返工逐克记账。

## 质量受权人如何核对

```bash
python -m process.demo          # 打开样例：逐克去向、缺口处理、报告引用、放行范围
python -m process.demo --check  # 机器核对：全部符合预期退出码 0
python -m unittest discover -s tests -v   # 21 项规则测试
```

`python -m process.demo` 分五节呈现：

* **A 物料台账** — 每个批号的建账/转入/转出/损耗/增重/结存与逐笔回放；
  总平式 `120.000 + 14.100 = 112.600 + 0.900 + 20.600`。
* **B 连续批记录** — 沿物料谱系（拆分/合批/返工）追溯每个成品批的完整工序链，
  标明版本、签署人、曲线状态（一次采集/补传后签署/挂偏差）。
* **C 偏差** — 温度缺口→整批返工；收率差异→台账回放后让步（记录错误）关闭。
* **D 报告↔样品↔批号** — 报告只对其样品与批号负责，旧报告/借用报告一目了然。
* **E 放行** — 借用上一批报告、借用原批旧报告的申请被拦截；最终只整批放行
  `a-1 70.100 kg` 与 `a-2-r1 42.500 kg`。

## 核心规则

### 1. 每次移动逐克守恒（`process/ledger.py`）

每笔 :class:`MaterialMovement` 独立满足：

```
全局   input_kg == output_kg + loss_kg
来源批 转出 + 损耗分摊 == input_kg
目标批 转入之和 == output_kg
```

拆分必须给出各子批分量；合批/辅料加入必须给出各来源分量与损耗分摊；
同批加工（水分散失）用有符号损耗记账；过账后任何批号结存不得为负。
`Ledger.trace(lot)` 可逐笔回放某批号全部物料去向。

### 2. 工艺参数按品种+生效版本校验（`process/specs.py`）

* 每道工序的参数限度（黄酒比例、润制时长、炒制温度/时长、干燥水分…）与曲线
  温度窗口、采样间隔随版本走；
* 批记录只能引用记录时点 **正在生效的最新版本**——已废止、未生效、非最新
  版本一律拒绝；
* 实质工序（净→切→加酒→润→炒→干燥→包装）沿谱系严格连续，不得跳工序或倒序；
  取样只允许在干燥之后，可在包装前后重复（补采）。

### 3. 传感器补传 vs 已确认曲线（`process/batch.py`）

* **未签署**记录：传感器补传可合并新采样点（温度窗口同样校验），标注补传凭据；
* **已签署**记录：曲线冻结，任何修正都必须凭 **已评估的偏差单**，由偏差管理员
  执行，原曲线在审计日志中留痕。

### 4. 职责分离（`process/users.py`）

| 角色 | 权限 |
|---|---|
| `operator` 操作人 | 领料、拆分合批、工序记录、传感器补传、签署 |
| `qa` 现场质量 | 取样、出报告、登记偏差、补采复检 |
| `deviation_owner` 偏差管理员 | 评估/关闭偏差、凭偏差单修正已签署曲线 |
| `rework_planner` 工艺员 | 批准返工、建返工批、确认返工完成 |
| `qp` 质量受权人 | **唯一**放行决定人 |

### 5. 返工（`process/batch.py`）

偏差评估为返工后，工艺员凭已批准偏差单建立 `rework_of` 指向原批的新批号，
原批可用结存守恒地整体转入新批；新批必须自炒制起重做全部关键工序、独立取样、
独立出报告。放行时若引用原批旧报告，直接抛 `ReportBorrowingError`。

### 6. 放行闸门（`ProcessingPlatform.release`，仅 QP）

整批放行前逐项核验并收集全部不符合项（`ReleaseBlocked.failures`）：

1. 谱系连续批记录齐全、按序、全部签署；曲线缺口须有 **已关闭**偏差覆盖；
2. 终端批号自身有包装记录，台账无负结存；
3. 谱系内偏差全部关闭（含收率/温度…），本批未被判定报废；
4. 每张报告核对：批号一致、未作废、结论合格，样品取自本批且所跟记录已签署；
5. 返工批必须有本批新报告（不得借用原批旧报告）；
6. 部分放行数量不超过当前结存。

## 模块划分

```
process/
  contracts.py  角色、批号、移动、曲线、工序记录、样品/报告、偏差、返工、放行决定
  errors.py     领域异常（守恒/规格/记录状态/偏差状态/报告借用/放行拦截）
  users.py      用户与角色鉴权
  specs.py      版本化工艺规格与注册表（生效版本解析）
  ledger.py     逐克守恒物料台账与逐笔回放
  batch.py      平台主流程：连续记录、补传/签署/偏差修正、偏差流、返工、复检、放行
  scenario.py   fixtures/processing_batch.json 的场景驱动
  demo.py       质量受权人核对视图（含 --check 自动对账）
tests/
  test_platform.py  21 项规则测试（unittest，无第三方依赖）
fixtures/processing_batch.json  样例：缺口/补传、拆批、返工、收率、报告借用
```

Python 3.11+，仅标准库。
